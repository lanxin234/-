# 链易 · 基于区块链的二手交易平台

> 用智能合约解决二手交易的信任难题：**买家不怕付了钱不发货，卖家不怕发了货不付钱**

---

## 这个项目解决了什么问题

传统二手交易的死结：

```
买家：先给我货，我再付钱  ←→  卖家：先付钱，我再发货
        双方都不敢先动，交易僵持
```

**本项目的解法 —— 资金托管**：

```
买家付款 → 钱进【智能合约】（不是给卖家）→ 买家收货验证 → 合约自动放款给卖家
```

全程**不需要信任对方**，也不需要平台做中间人。合约代码公开、执行自动、记录不可篡改。

## 局域网内给同学用（多人共用）

这是本项目的目标场景：**你的电脑当服务器，同一个 WiFi 下的同学用手机或电脑访问。**

### 三步走

**① 启动服务**：双击 `start_server.bat`，或终端执行 `python backend/app.py`。

**② 把地址发给同学**：启动后控制台会打印类似：

```
同一局域网（同学/手机）访问：
    http://192.168.1.23:5000
```

同学用手机浏览器或电脑浏览器打开这个地址就行。**不需要装任何东西。**

**③ 保持电脑开着**：这个窗口关掉，服务就停了，所有人都访问不了。
另外别让电脑休眠（电源设置里把「睡眠」关掉，或设成「从不」）。

### 连不上怎么办

按顺序排查：

| 现象 | 原因 | 解决办法 |
|---|---|---|
| 同学完全打不开 | Windows 防火墙拦了 5000 端口 | 用**管理员**权限开一个终端，执行一次下面那条命令 |
| 你自己能开，同学不行 | 连的不是同一个 WiFi，或校园网做了 AP 隔离 | 换成手机热点，大家连同一个热点 |
| 手机能开但很卡 | 电脑休眠了 | 关掉睡眠设置 |

放行防火墙（管理员权限，**只需执行一次**）：

```cmd
netsh advfirewall firewall add rule name="BlockchainMarket" dir=in action=allow protocol=TCP localport=5000
```

不用了可以删掉这条规则：

```cmd
netsh advfirewall firewall delete rule name="BlockchainMarket"
```

### 关于容量和数据

- **最多 199 位用户**（链上预置 200 个账户，1 个留给平台方）。一个班用足够了。
- **数据会落盘**。今天关掉电脑，明天再启动，昨天上架的商品和交易记录都还在。
- 想清空重来：页面右上角「区块链浏览 → 重置整条链」，或者直接删掉 `data/` 目录。

### 想备份

把整个 `data/` 目录复制走就行 —— 链和业务数据都在里面。
恢复到另一台机器上，把 `data/` 放回去，启动服务即原样续用。

### 安全提醒

- 这是**局域网演示环境**，不要放到公网上。没有 HTTPS，密码是明文传输的。
- 页面上的「重置整条链」按钮**没有鉴权**，任何人都能点。局域网内请只给可信的人访问。
- `data/app_state.json` 里存的是 **scrypt 加盐哈希**，不是明文密码，但还是别随手外传。

## 用户登录的安全验证

这是本项目在"能不能用"之外的**安全底线**。改造前后对比：

| | 改造前 | 改造后 |
|---|---|---|
| 身份来源 | 请求体里的 `username` 字段 | 服务端解出的登录令牌 |
| 能否冒名 | **能**。填 `alice` 就能以 alice 身份下单、下架 | 不能。请求体里写什么都不作数 |
| 密码 | 无 | scrypt 加盐哈希存储 |
| 登录态 | 无，刷新即丢 | 令牌存 localStorage，刷新后自动恢复 |
| 暴力破解 | 无防护 | 5 次错误锁定 5 分钟 |

### 四层防护

**第 1 层 · 密码不落明文（scrypt 加盐哈希）**

```python
hash_password("MyPass123")
# → "scrypt$<16字节随机盐>$<32字节派生密钥>"
```

- 每个账号的盐都不同 → 相同密码在库里长得完全不同，无法用彩虹表反查
- scrypt 是**计算密集型**算法（N=2¹³, r=8, p=1，单次约 90ms）→ 暴力枚举代价极高
- 校验用 `hmac.compare_digest` **恒定时间比较**，防止通过响应时间差反推密码

> 为什么把 N 从 2¹⁴ 降到 2¹³？2¹⁴ 单次哈希要 190ms，演示时登录有明显卡顿。2¹³（约 90ms）在演示体验和抗暴力破解之间取了平衡点，代码里有注释说明。

**第 2 层 · 无状态签名令牌（HMAC-SHA256）**

```
token = base64url(载荷JSON) + "." + base64url(HMAC-SHA256(载荷, 服务端密钥))
载荷   = {"u": "alice", "iat": 签发时间, "exp": 过期时间, "jti": 随机ID}
```

- 服务端不存 session，靠**密钥签名**验证真伪 → 改一个字符签名就对不上
- 默认有效期 **2 小时**；快到期（剩余 <15 分钟）时响应头带 `X-Renewed-Token` 自动续期
- 密钥持久化在 `backend/.secret_key`，也可用环境变量 `MARKET_SECRET_KEY` 覆盖
- 登出把 token 加入黑名单，旧 token 立即失效

**第 3 层 · 身份只认 token（堵住越权）**

所有写操作都挂了 `@require_auth`，身份统一从 token 解出：

```python
username = get_auth_user()   # ✅ 服务端解出来的，可信
# username = data.get("username")   # ❌ 改造前的写法，前端说啥就是啥
```

覆盖的 8 个接口：`/api/logout`、`/api/me`、`/api/items`(POST)、`/api/buy`、`/api/confirm`、`/api/remove`、`/api/rate`、`/api/my_items`。

**第 4 层 · 防暴力破解**

同一账号 5 分钟内错 5 次 → 锁定 5 分钟，期间**即使密码正确也拒绝**（429）。

### 密码强度规则

注册时强制校验：长度 ≥8 位、必须同时含字母和数字、不能是纯重复字符、不在常见弱口令表里（`password` / `12345678` / `qwerty` 等）。

### 验证测试

```bash
"$PY" scripts/test_auth.py
```

50 个断言，覆盖 9 组场景：注册校验、密码存储、登录、**令牌篡改**、**越权/身份冒用**、登出作废、**暴力破解锁定**、`/api/my_items` 数据隔离、敏感信息泄漏检查。

实测拦截效果：

| 攻击方式 | 结果 |
|---|---|
| Bob 拿自己 token，请求体写 `username: "alice"` 下单 | 链上买家是 **Bob** —— 冒名失败 |
| 不带 token 直接上架 | `401 登录已失效，请重新登录` |
| 篡改 token 签名的最后 4 位 | `401` |
| 只提交去掉签名的裸载荷 | `401` |
| 连续输错密码 5 次后再输正确密码 | `429` 锁定，正确密码也进不去 |

> **一个刻意的设计**：重置整条链时**不会**清空账号密码。否则每次重置都要重新注册所有账号，演示时很麻烦。
> 代价是链重置后用户名仍被占用 —— 直接**用原账号登录**即可（会自动分配新的链上账户）。

### 登录态为什么不会"莫名其妙失效"

早期版本经常弹「登录已失效」，排查后发现是**四个独立原因叠在一起**，现在逐一堵住了：

| 原因 | 现象 | 修复 |
|---|---|---|
| **重置链后地址映射丢失** | 令牌签名有效、账号也还在，但 `user_sessions` 被清空 → 每个接口都查不到链上地址 | 新增 `state.ensure_account()` 自愈：地址没了就**自动补一个**，而不是报错把用户踢下线 |
| **错误语义混乱** | 无地址时有的接口返回 400「账号异常」、有的返回 404「账号不存在」，前端只能瞎猜 | 统一为两个明确错误码：真失效 → `401 AUTH_REQUIRED`；账户池满 → `503 ACCOUNT_POOL_FULL` |
| **掉线后没有登录入口** | 被踢下线时界面只剩一个只读的用户条，想重登只能手动刷新页面 | 新增 `renderAuthForm()`：掉线后**原地重建登录表单**，并把掉线原因显示在表单上 |
| **带图片上架的请求漏带令牌** | **只有附了图片才报**「登录已失效」——那条分支用了裸 `fetch`，绕过了会自动带令牌的 `api()` 封装 | 改走 `api('/api/items', { method:'POST', body: fd })`；并用测试静态扫描全站防止再写漏 |

另外「重置整条链」按钮以前会 `location.reload()` 整页刷新，把用户静默丢回登录页 —— 现在改为原地还原表单并明确提示「整条链已重置，请重新登录」。

**验证方式**（`scripts/test_login_flow.py` + `scripts/test_frontend_auth.js` + `scripts/test_publish_auth.js`）：

```
【2】登录 → 重置链（保留账号）→ /api/me 仍返回同一用户（不再 404）   ✓
【3】乱码令牌 / 登出后的令牌 → 401 + AUTH_REQUIRED                    ✓
【4】账户池用尽 → 503 + ACCOUNT_POOL_FULL，且已登录用户不受连累        ✓
【前端】掉线后登录表单原地重建、原因可见、可立即重新提交               ✓
【上架】带图片 / 不带图片 提交都带 Authorization 头                    ✓
```

## 四大核心功能

### 1. 商品上链上架
商品名称、描述、价格写入区块链。记录**永久保存、不可篡改**。

### 2. 担保交易托管（核心）
买家付款进入合约托管，确认收货后才放款。合约里 `buyItem()` 和 `confirmReceived()` 两个函数配合完成。

### 3. 所有权转移
交易完成后，商品所有者从卖家变为买家，链上可查。`getItem()` 能查到 `seller` 和 `buyer` 两个字段的变化。

### 4. 信誉评价
交易完成后双方互评（1-5 星），评分累加在链上。**每笔交易每人只能评一次**，无法刷分。

## 三大进阶功能

### 1. 商品图片上传（内容寻址，IPFS 思路）

图片不是随便存一下，而是按**内容哈希**存储 —— 这跟 IPFS 的原理一致。

```
上传图片 → 算出 SHA-256(文件内容) → 用哈希当文件名存下来 → 哈希写进区块链
```

带来的三个性质：

| 特性 | 说明 |
|---|---|
| **天然去重** | 同一张图上传多次只存一份（内容相同 → 哈希相同 → 同一个文件） |
| **防篡改** | 改一个字节哈希就完全变样，链上存的是旧哈希，一对不上立刻暴露 |
| **可校验** | 详情页点「重新计算并校验」，后端重算一遍哈希与链上比对 |

> **诚实说明**：这里用的是**本地内容寻址存储**，不是真正接入 IPFS 网络（IPFS 节点会触发系统的应用控制策略拦截）。但"地址由内容决定"这个核心机制是完全一致的，代码里也标了注释，答辩时讲清这个区别即可。

### 2. 交易时间线（从链上事件还原）

每件商品都有一条完整的流转记录，**数据不是后端记的账，而是从区块链事件日志里读出来的**：

```
📦 商品上架        卖家挂出，价格写入链上
   ↓
🔒 买家下单        资金进入合约托管，卖家拿不到
   ↓
✅ 买家确认收货    合约自动放款（扣 1% 平台费）
   ↓
⭐ 双方评价        评分永久记录
```

合约在每一步操作时都会 `emit` 一个事件（`ItemListed` / `ItemPurchased` / `ItemDelivered` / `Rated`），事件永久存在链上。时间线就是把这些事件按区块顺序拼起来 —— 所以它**无法被伪造**，看到的就是链上真实发生过的。

### 3. 数据看板（实时统计）

六个核心指标卡片 + 三张图表：

| 图表 | 内容 |
|---|---|
| **成交额趋势折线图** | 从 `ItemDelivered` 事件还原每日成交额 |
| **分类成交占比环形图** | 各分类成交金额占比（无成交时退化为上架数量占比） |
| **价格区间分布柱状图** | 5 档价格区间（0-0.1 / 0.1-0.5 / 0.5-1 / 1-5 / 5+ ETH） |

指标卡片包括：商品总数、累计成交额（GMV）、当前托管资金、交易中订单、平台手续费收入、已下架数量。

> **关键点**：看板没有单独存一份"统计表"。每次打开都重新从链上逐条读取商品和事件再算一遍，所以**链上一变，看板立刻跟着变**，不存在数据不同步的问题。

### 界面设计要点

**状态色系统一**：在售（绿）、交易中（橙）、已售出（紫）、已下架（灰），全站一致。

**关键操作有摩擦**：购买、确认收货这类不可逆操作，都会弹出确认框并列出资金明细。比如确认收货时会明确显示：

```
商品          索尼降噪耳机 WH-1000XM4
金额          0.8 ETH
放款金额      0.792 ETH
平台手续费    0.008 ETH
```
让用户清楚知道点下去会发生什么。

**分类和图片哈希不占链上独立字段**：都编码在商品描述里（`[分类]数码电子|图片哈希|实际描述`），读取时解析。这样**不用修改已部署的合约**就能扩展字段——这是区块链应用开发中常见的向后兼容技巧。

## 常见问题

### Q: 数据重启后没了？

**不会了。** 链数据已经落盘到 SQLite，关掉服务再打开，商品、订单、余额、信誉、交易时间线全都还在。

两个文件管所有数据（都在项目根目录的 `data/` 下，已加进 `.gitignore`）：

| 文件 | 装的是什么 |
|---|---|
| `data/chain.sqlite3` | 链本体：区块、交易、事件日志、合约存储 |
| `data/app_state.json` | 业务数据：账号哈希、昵称、用户↔地址映射、合约地址 |

想**恢复出厂**就把 `data/` 整个目录删掉，下次启动会重新建链。
页面上「区块链浏览 → 重置整条链」也一样，但默认保留账号密码。

> 原理：py-evm 建链时会读环境变量 `CHAIN_DB_BACKEND_CLASS`（点分导入路径），
> 默认指向内存后端。`backend/chaindb.py` 把这个换成了 SQLite 支撑的实现，
> 于是整条链自动落盘 —— 不需要自己写"快照 → 回放重建"，也不会丢事件日志。

### Q: ETH 是真钱吗？

**完全不是**。测试链的以太坊是凭空生成的测试币，没有任何货币价值，不涉及任何真实资金。

### Q: 测试账户有几个？

**200 个**，每个初始 **100 测试 ETH**。平台方占用 1 个，剩下 **199 个**可分配给注册用户。

> 为什么是 100 而不是 eth-tester 默认的 100 万？因为演示时读数「余额 999999.99」没有任何意义。
> 商品价格区间是 0.05 ~ 3.2 ETH，100 ETH 够买卖几十次，数字也一眼能看懂。
> 这是**直接写进创世状态**的（早期版本是建完链再去改 py-evm 底层账户 trie，
> 那套写法依赖内部实现、换个版本就可能失效，现在不需要了）。

想改数量，设环境变量（只对新建的链生效）：

```bash
CHAIN_ACCOUNTS=500 "$PY" backend/app.py
```

改完记得删掉 `data/` 目录，否则会沿用旧链。

### Q: 怎么让下次打开不用再登录？

登录时勾上**「记住我」**（用户名下面那个复选框），会签发一个 **30 天**的令牌，
关掉浏览器、第二天再打开仍然是登录状态。不勾的话令牌 2 小时过期。

配套行为：

- 勾了之后会记住**用户名**，下次打开自动填好，只用输密码
- **密码不会存在浏览器里** —— 只存用户名和令牌，密码一旦明文落 localStorage，
  一个 XSS 就能把所有账号拿走
- 点「退出登录」会把记住的用户名一起清掉（换人用同一台电脑时安全）
- 令牌过期导致的自动掉线**不会**清掉用户名，省得重新敲

> 登出的令牌会记进黑名单并**落盘**。这点是必须的：不落盘的话，
> 30 天的令牌登出后一重启就又活过来了。

### Q: 忘记密码了怎么办？

演示环境没有找回密码的设计（真实系统会走邮箱/短信验证）。直接**重置整条链后换一个用户名重新注册**即可。

### Q: 用户名被占用了，但链已经重置了？

这是刻意的：重置链**不清空账号密码**，否则每次重置都要重新注册所有账号太麻烦。直接用原账号**登录**就行，系统会自动分配一个新的链上账户。

如果确实想连账号一起清空（比如要重复跑自动化测试），传一个参数：

```js
fetch('/api/reset', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({wipe_credentials: true})
})
```

这样账号密码一并清空、所有旧令牌立即失效，注册过的用户名重新可用。`scripts/test_auth.py` 和 `scripts/test_new_features.py` 开头都会自动这样重置，所以它们可以反复运行。

### Q: 怎么重置数据？

页面右上角「区块链浏览 → 重置整条链」，或者在浏览器控制台执行：
```js
fetch('/api/reset', {method:'POST'})
```

刷新页面也行（前端登录态保留，链上数据清空）。

### Q: 改完代码后怎么同步到「项目源代码」归档目录？

归档目录是 `C:/Users/25191/Desktop/项目源代码`（纯副本，不含 `.git`）。**每次改完代码跑这一条即可**：

```bash
PY=C:/Users/25191/.venvs/base/Scripts/python.exe
"$PY" scripts/sync_source.py
```

它会：
1. 按 `.gitignore` 同样的规则**排除** `.git` / `__pycache__` / `build` / `uploads` / 日志 / `.secret_key` / 本地临时文件
2. 只复制**新增或内容有变**的文件，不重复搬运
3. 复制后**逐个校验 md5**，全部一致才算成功（有任何不一致就非零退出）

常用参数：

```bash
"$PY" scripts/sync_source.py --dry-run    # 只看差异，不实际复制
"$PY" scripts/sync_source.py --prune      # 顺手删掉归档里已不存在的旧文件
"$PY" scripts/sync_source.py --dest "D:/别的目录"   # 同步到别的归档目录
```

> **刻意不做的事**：默认**不删除**归档里的任何文件（避免误伤），多余文件只提示、不清理，需清理要显式加 `--prune`。
> 另外脚本**不会**把 `.secret_key`（令牌签名密钥）、日志、`__pycache__` 带进归档 —— 归档里只放源代码。
